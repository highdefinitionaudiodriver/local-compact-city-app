# ローカルコンパクトシティ
## 住民提案・デジタル署名プラットフォーム — 自治体向けご案内

---

## なぜ今、住民提案のデジタル化が必要か

| 現状の課題 | 自治体の負担 |
|---|---|
| 紙の請願は集計・保管・電子化が大変 | 担当職員が深夜まで仕分け作業 |
| ネット署名（Change.org 等）は本人確認が無い | 受け取っても公文書として扱えない |
| 議会への提出資料に「定量的な熱量データ」が無い | 議員が判断材料に困る |
| 住民の関心を肌感で掴めない | 行政施策の優先順位付けが難しい |

---

## 本プラットフォームが解決すること

### ✅ 「無視できない重み」を持つ住民の総意を可視化

- **マイナンバーカード（JPKI）認証**による居住確認済み住民の電子署名
- 二重投票を **データベース一意制約**で物理的に防止
- 個人情報は**ハッシュ化**して保存。マイナンバー本体はシステムに触れない

### ✅ 行政が公式に扱える「公文書品質」の出力

- ボタン一つで **A4 PDF レポート**を生成（Noto Sans JP 同梱、印字崩れなし）
- **HMAC-SHA256 改ざん検知**：受け取った文書が改ざんされていないか専用ページで再検証可能
- Excel CSV 出力で議会提出資料にそのまま添付可能

### ✅ リアルタイムの統計ダッシュボード

- **時系列グラフ**：請願がいつ加速したか可視化（SNS 拡散時期との対応分析）
- **自治体別内訳円グラフ**：地元住民の比率を一目で把握 → 議会説得材料に
- **append-only 監査ログ**：誰が・いつ・どの状態に変更したか追跡可能

## 想定する導入シナリオ

### シナリオ A：住民請願プラットフォームとして本格運用

- 自治体公式サイトに本ツールを設置
- 一定署名数（例：人口の 1% 以上）で議会への自動付託
- 議会傍聴・住民説明会と連動

### シナリオ B：実証実験（PoC）

- 特定地域・特定テーマ（例：「中心市街地活性化請願」）で 3 ヶ月限定運用
- 効果測定後、本格導入を判断
- 当方が PoC 実施支援・カスタマイズ・データ分析を行います

### シナリオ C：議員・市民団体向けの簡易デモ

- ノートPC1台で住民役・職員役のロールプレイ実演（所要 10 分）
- 改ざん検知デモで「公文書品質」の説得力を体感
- **実演無償でお伺いします**

## 技術仕様（要約）

| 項目 | 内容 |
|---|---|
| フロントエンド | Next.js 16 (App Router) / TypeScript / Tailwind CSS |
| バックエンド | Next.js Server Actions（ローカル運用） |
| データベース | Prisma + SQLite（自治体内ネットワーク完結） |
| 認証 | NextAuth.js v5 + JPKI モック（実機接続対応設計） |
| PDF生成 | @react-pdf/renderer + Noto Sans JP |
| 改ざん検知 | HMAC-SHA256（CSV/PDF メタデータ埋込） |
| ライセンス | MIT（無料・改変可） |
